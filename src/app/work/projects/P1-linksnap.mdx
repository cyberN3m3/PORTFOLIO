## Overview

Built and deployed LinkSnap, a serverless URL shortener. Three Lambda functions (create, redirect, analytics) sit behind an HTTP API in API Gateway, with two DynamoDB tables for the links and their click history. There are no servers to patch, nothing runs while nobody is clicking, and the whole stack is created and destroyed with Terraform. At portfolio traffic it stays inside the AWS Free Tier.

## Key Features

- **Fast redirects**: a single DynamoDB key lookup on the short code, then an HTTP 301 to the original URL.
- **Click analytics**: every redirect increments a click counter and records the timestamp, referrer and user agent; the analytics endpoint returns totals and top referrers.
- **Self-cleaning data**: DynamoDB TTL expires old links and analytics records automatically.
- **Automated Deployment**: Entire infrastructure defined as code (IaC) using Terraform, enabling one-click reproducibility and version-controlled environment changes.
- **Secure by Design**: Implementation of AWS IAM least-privilege roles, secure HTTPS communication via CloudFront, and automated input sanitization.
- **Pay-per-request**: on-demand DynamoDB capacity and Lambda pricing mean the bill follows traffic; at demo traffic it stays in the Free Tier.

## Technologies Used

- **AWS Lambda**: Event-driven compute handling the core shortening logic and asynchronous analytics processing.
- **Amazon DynamoDB**: two on-demand tables, one for URL mappings and one for click events (keyed by short code and timestamp).
- **Amazon API Gateway (HTTP API)**: routes for creating links, redirecting and reading analytics.
- **Terraform**: Infrastructure as Code (IaC) for reproducible and version-controlled cloud environments.
- **AWS CloudFront**: Global distribution for the frontend, ensuring low-latency delivery of the management interface.

## Challenges and Learnings

The main design question was how to keep redirects fast while still recording analytics. I kept the redirect path to one key lookup and wrapped the analytics writes so a failure there can never block a redirect. I also split the data into two tables: link lookups are read-heavy and keyed by short code, while click events are write-heavy and keyed by short code plus timestamp, so each table fits its access pattern. Keeping each function small and on Python 3.11 kept cold starts short.

## Outcome

LinkSnap is a working serverless API that costs nothing while idle and scales with demand without any capacity planning. It gave me hands-on practice with Lambda, API Gateway HTTP APIs, DynamoDB key design and TTL, least-privilege IAM, and a Terraform stack I can reuse for other serverless APIs.
