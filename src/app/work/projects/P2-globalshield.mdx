## Overview

Designed and deployed a multi-region disaster recovery setup on AWS with automatic failover from us-east-1 to us-west-2. The site is served from S3 buckets in both regions behind one CloudFront distribution; if the primary origin returns errors, CloudFront retries the request against the secondary without anyone touching DNS. Running costs stay within the AWS Free Tier.

## Key Features
- **Automated Failover**: CloudFront Origin Groups provide active-passive traffic shifting with zero manual intervention, ensuring continuous availability during regional outages.
- **Multi-Region Resilience**: Redundant hosting across US East and US West regions with S3 static website hosting, eliminating single points of failure.
- **Real-Time Dashboard**: Professional dark-mode monitoring interface with simulated incident and recovery modes, providing visual feedback on system health and failover status.
- **Infrastructure as Code**: Complete stack deployed via Terraform, enabling one-click reproducibility and version-controlled infrastructure changes.
- **Health Monitoring**: a Route 53 health check watches the primary endpoint, so an outage is visible even while CloudFront is already serving the backup.

## Technologies Used

- **AWS CloudFront**: Global CDN serving as entry point with SSL termination and intelligent origin routing.
- **Amazon S3**: Multi-region static website hosting with region-specific dashboards.
- **AWS Route 53**: health check on the primary endpoint.
- **Terraform**: Complete infrastructure automation and deployment orchestration.
- **HTML5 & Tailwind CSS**: High-tech terminal aesthetic with JetBrains Mono and Inter fonts for professional monitoring interface.

## Challenges and Learnings

The key challenge was getting real failover without paying for idle servers in a second region. CloudFront origin groups solved it: failover happens per request at the edge, and the standby region is just an S3 bucket that costs almost nothing until it is needed. Additionally, creating an intuitive dashboard that clearly communicates system state during both normal operations and failover events required careful UX design to balance technical information with accessibility.

## Outcome

The project shows an active-passive disaster recovery pattern working end to end at almost no cost, and taught me multi-region Terraform (provider aliases), CloudFront origin groups and failover criteria, and how to show system state clearly on a dashboard. The same pattern is a sensible first step for any static site or front end that must survive a regional outage.
