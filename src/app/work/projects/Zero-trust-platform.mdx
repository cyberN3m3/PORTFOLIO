## Overview

Architected and deployed a production ready remote workforce management platform combining a React + TypeScript frontend with a fully Terraform-managed AWS backend. The infrastructure implements zero trust principles across a 3-tier VPC with EC2 Auto Scaling, RDS PostgreSQL, ALB and Cognito MFA while keeping costs down with Free Tier instance sizes, one NAT Gateway shared by both private subnets and a single ALB. A real time monitoring dashboard surfaces security events, active user metrics, and system uptime, delivering enterprise-grade observability at startup-friendly costs.

## Key Features

- **Zero-Trust Architecture**: All backend resources deployed into private subnets by default, with least-privilege security groups enforcing port-specific, role-based access across every tier.
- **AWS Cognito MFA**: User authentication backed by Cognito user pools and optional TOTP multi-factor authentication.
- **Infrastructure as Code**: Modular Terraform configuration spanning VPC, EC2, RDS, ALB, Cognito, and CloudWatch — enabling one-command provisioning and fully version-controlled infrastructure changes.
- **Cost-Aware Design**: one NAT Gateway shared by both private subnets instead of one per AZ (about $32/month saved), a single ALB with path-based routing for every service, and Free Tier sizes for EC2 and RDS. The NAT Gateway is the main running cost, so the stack is destroyed after demos.
- **Real-Time Security Dashboard**: Live monitoring interface with Recharts-powered activity visualization, severity-filtered security event logs, and 60fps Framer Motion micro-interactions.
- **Continuous Deployment**: Vercel builds and deploys the frontend on every push.
- **Availability**: the ALB and API instances span two Availability Zones and the Auto Scaling group replaces unhealthy instances; RDS is single-AZ to stay in the Free Tier (one setting turns on Multi-AZ failover).
- **Secrets Management**: database credentials live in AWS Secrets Manager, not in the code.

## Technologies Used

- **AWS VPC**: 3-tier network architecture (public, private, and database subnets) across two Availability Zones, providing full network isolation for compute and data layers.
- **EC2 Auto Scaling Group**: t3.micro instances from a launch template, kept at the desired count and replaced when unhealthy.
- **RDS PostgreSQL 15**: db.t3.micro instance in private database subnets, with AES-256 encryption at rest and TLS 1.2 in transit for secure, managed relational storage.
- **Application Load Balancer**: HTTPS termination with path-based and host-based routing, consolidated across all services to minimize per-resource costs.
- **AWS Cognito**: managed user pool with optional TOTP MFA.
- **AWS Secrets Manager**: stores the database credentials outside the application code.
- **Terraform 1.6**: Modular IaC across five domain modules (vpc, ec2, rds, cognito, monitoring) with environment-specific configurations under `environments/prod`.
- **React 18.2 + TypeScript 5.3**: Strict-mode frontend with custom hooks, lazy loading, and code splitting for a 95+ Lighthouse score and ~180kb gzipped bundle.
- **Tailwind CSS 3.4 + Inter Font System:** Enterprise-grade dashboard interface with monochromatic slate palette and minimal animations. Designed following modern SaaS patterns (Linear, Vercel) for professional credibility over decorative aesthetics. Achieves 95+ Lighthouse score with optimized bundle size.
- **Vercel**: builds and deploys the frontend automatically on every push.

## Challenges and Learnings

This build surfaced four engineering problems that each, in their own way, came down to toolchain boundaries not playing nicely together. The first was TypeScript strict mode breaking the build over unused variable declarations inside custom hooks. It sounds minor, but fixing it properly meant auditing every custom hook's destructured return values and cutting dead code paths until the project hit 100% strict mode compliance. The second issue was easy to miss at first glance: shell variable syntax (`${VAR}`) inside Terraform EC2 user data scripts was being swallowed by Terraform's own interpolation engine before the script ever ran. Switching to `$$` escaping and single-quoted heredocs solved it. Third, ALB health checks were failing because the Express backend had no CORS headers, so the load balancer simply refused to route traffic to those instances. Adding origin-aware CORS middleware before the router cleared it up. Last was a batch of eight `npm audit` vulnerabilities flagged right before a Vercel deployment. After tracing the dependency tree, all eight turned out to be scoped to devDependencies with no production exposure, and targeted patches resolved them cleanly. The bigger takeaway from all of this was that IaC templating, TypeScript compilation, network policy, and dependency management each have their own rules, and those rules start conflicting the moment you combine them in a real production pipeline.

## Outcome

The project shows a 3-tier, zero-trust network on AWS: only the load balancer is public, the API servers and database sit in private subnets, and every tier only accepts traffic from the one before it. The cost table in the GitHub README is honest about where the money goes (the NAT Gateway) and what I traded for it. Next steps I would take for production: Multi-AZ RDS, mandatory MFA, Secrets Manager rotation, a CPU-based scaling policy and a GitHub Actions pipeline for the Terraform.
