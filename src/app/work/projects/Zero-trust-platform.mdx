## Overview

A remote workforce management platform: a React + TypeScript dashboard on the front, and an AWS backend built entirely in Terraform. The network follows zero-trust rules across three tiers. Only the load balancer is public; the API servers (EC2 Auto Scaling) and the PostgreSQL database sit in private subnets, and sign-in goes through Cognito with optional MFA. To keep the bill down I used Free Tier instance sizes, one NAT Gateway shared by both private subnets and a single ALB. The dashboard shows security events, active users and uptime.

## What it does

- **Private by default**: every backend resource is in a private subnet, and each tier only accepts traffic on its own port from the tier in front of it.
- **Sign-in with MFA**: Cognito user pools with optional TOTP multi-factor authentication.
- **All in Terraform**: VPC, EC2, RDS, ALB, Cognito and CloudWatch are Terraform modules, so the stack is created with one command and every change is version-controlled.
- **Cost-aware**: one NAT Gateway shared by both private subnets instead of one per AZ (about $32/month saved), one ALB with path-based routing for every service, and Free Tier sizes for EC2 and RDS. The NAT Gateway is the main running cost, so I destroy the stack after demos.
- **Security dashboard**: activity charts (Recharts), security event logs filtered by severity, and small animations with Framer Motion.
- **Automatic frontend deploys**: Vercel builds and deploys the frontend on every push.
- **Availability**: the ALB and API instances span two Availability Zones and the Auto Scaling group replaces unhealthy instances. RDS is single-AZ to stay in the Free Tier; one setting turns on Multi-AZ failover.
- **No secrets in code**: database credentials live in AWS Secrets Manager.

## Technologies Used

- **AWS VPC**: public, private and database subnets across two Availability Zones.
- **EC2 Auto Scaling**: t3.micro instances from a launch template, kept at the desired count and replaced when unhealthy.
- **RDS PostgreSQL 15**: db.t3.micro in private database subnets, encrypted at rest (AES-256) and in transit (TLS 1.2).
- **Application Load Balancer**: HTTPS termination with path- and host-based routing, one ALB for all services to keep costs down.
- **AWS Cognito**: managed user pool with optional TOTP MFA.
- **AWS Secrets Manager**: database credentials outside the application code.
- **Terraform 1.6**: five modules (vpc, ec2, rds, cognito, monitoring) with the production configuration under `environments/prod`.
- **React 18.2 + TypeScript 5.3**: strict mode, custom hooks, lazy loading and code splitting (about 180 KB gzipped).
- **Tailwind CSS 3.4 and Inter**: a plain slate palette with minimal animation.
- **Vercel**: builds and deploys the frontend on every push.

## Challenges and Learnings

Four problems came from tools that don't quite agree with each other:

- **TypeScript strict mode broke the build** over unused variables in custom hooks. I went through each hook's return values, removed the dead code and got the project fully strict-mode clean.
- **Shell variables vanished from EC2 user data.** Terraform was interpolating `${VAR}` before the script ever ran. Escaping with `$$` and using single-quoted heredocs fixed it.
- **ALB health checks failed** because the Express backend sent no CORS headers. Adding origin-aware CORS middleware before the router fixed it.
- **`npm audit` flagged eight vulnerabilities** just before a Vercel deploy. All eight were in devDependencies with no production exposure, and targeted updates cleared them.

The lesson: Terraform templating, TypeScript, network rules and dependencies each have their own rules, and they only start to clash once you put them together in one pipeline.

## Outcome

The project shows a 3-tier, zero-trust network on AWS: only the load balancer is public, the API servers and database are private, and each tier only accepts traffic from the one before it. The cost table in the GitHub README shows where the money goes (the NAT Gateway) and what I traded for it. For production I would add Multi-AZ RDS, mandatory MFA, Secrets Manager rotation, a CPU-based scaling policy and a GitHub Actions pipeline for the Terraform.
